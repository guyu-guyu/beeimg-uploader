# 图床图片管理功能设计

状态：Proposed

建议目标版本：1.2.0

最后更新：2026-07-31

## 1. 背景

插件目前只负责把图片上传到蜜蜂图床并在笔记中插入远程链接。用户若要确认历史上传内容、复制已有链接或删除误上传图片，必须离开 Obsidian 前往图床后台。

蜜蜂图床同时提供旧版和新版图库接口。现有插件已经围绕 `/api/v1` 完成认证、错误解析、上传和相册查询，因此首期图片管理应延续旧版接口，在不改变现有上传行为和 Token 要求的前提下提供完整的浏览、预览和单张删除流程。

领域术语以 [CONTEXT.md](../CONTEXT.md) 为准。

## 2. 目标

- 在 Obsidian 内查看当前账号的图床图片。
- 分页浏览图片，并按关键字、相册、公开状态和顺序筛选。
- 使用缩略图快速浏览，点击后查看大图和基础元数据。
- 显示每张图床图片在当前仓库中的引用次数。
- 复制原图链接或 Markdown 图片语法。
- 对单张图片执行有明确风险提示的永久删除。
- 兼容桌面端和移动端，不引入 Electron 专属能力。
- 复用现有认证方式：API Token 或账号密码登录。

## 3. 非目标

首期不包含以下能力：

- 批量选择和批量删除。
- 修改图片名称、描述、公开状态、标签或所属相册。
- 新建、修改或删除相册。
- 浏览其他用户的公开图片或蜜蜂图床广场。
- 自动修复因删除而失效的笔记链接。
- 统计普通文字链接、Canvas、PDF 或其他非 Markdown 文件中的图片使用情况。
- 将 API 全面迁移到 `/api/v2`。
- 离线缓存完整图库或原图文件。

## 4. API 选择

### 4.1 首期使用旧版接口

| 能力 | 请求 | 用途 |
|---|---|---|
| 图片列表 | `GET /api/v1/images` | 分页、搜索、筛选并取得预览信息 |
| 删除图片 | `DELETE /api/v1/images/{key}` | 按图片 Key 永久删除单张图片 |
| 相册列表 | `GET /api/v1/albums` | 填充相册筛选选项 |

列表接口支持以下查询参数：

| 参数 | 取值 | 插件行为 |
|---|---|---|
| `page` | 正整数 | 当前页码 |
| `q` | 字符串 | 名称关键字，输入停止 300 ms 后查询 |
| `order` | `newest`、`earliest`、`utmost`、`least` | 默认 `newest` |
| `permission` | `public`、`private` | 未选择时省略 |
| `album_id` | 正整数 | 未选择相册时省略 |

选择旧版接口的原因：

1. 当前插件已经使用同一 `/api/v1` 基地址和 Bearer Token。
2. 列表响应直接提供删除所需的 `key`、缩略图和原图链接。
3. 不要求现有用户重新创建带新版细粒度权限的 Token。
4. 改动集中在新增客户端方法和图库视图，不影响现有上传链路。

### 4.2 暂缓新版接口

新版接口使用 `/api/v2/user/photos`，提供图片详情、标签以及按 ID 数组批量删除，但需要区分 `user:photo:read` 和 `user:photo:write` 权限。后续迁移时必须新增独立的 v2 基地址、Token 能力检测和 v1/v2 标识转换，不能把图片 Key 当作图片 ID 使用。

### 4.3 文档与实际行为差异

Apifox OpenAPI 的接口级 `security` 为空，但实际站点对 `/api/v1/images` 和 `/api/v2/user/photos` 均返回未认证错误。所有图库请求必须携带：

```http
Authorization: Bearer {token}
Accept: application/json
```

## 5. 用户入口与界面

### 5.1 入口

- 左侧功能区增加图片图标，提示文字为“打开蜜蜂图库”。
- 命令面板增加“打开蜜蜂图库”。
- 重复执行命令时复用已有视图并将其激活，不创建重复叶子。

### 5.2 图库视图

使用 Obsidian `ItemView` 创建独立工作区视图，视图标题为“蜜蜂图库”。整体由工具栏、状态区、图片网格和分页栏组成。

工具栏控件：

- 搜索框：按关键字过滤。
- 相册下拉框：包含“全部相册”和当前账号的相册名称。
- 公开状态下拉框：全部、公开、私有。
- 排序菜单：最新、最早、最大、最小。
- 刷新图标按钮：重新请求当前查询。

图片网格：

- 每项显示稳定比例的缩略图区域，避免图片加载造成布局跳动。
- 显示文件名、尺寸、格式化后的文件大小和上传时间。
- 使用链接图标和数字显示当前仓库引用次数；索引未完成时保留固定宽度的加载状态。
- 卡片操作使用图标按钮：复制链接、复制 Markdown、删除。
- 图片和文件名均可打开预览。
- 缩略图使用 `loading="lazy"`。
- 桌面端自适应多列，窄屏和移动端至少保持单列可用。

状态区必须覆盖：

- 首次加载。
- 条件切换后的刷新。
- 空图库。
- 筛选无结果。
- 未配置认证信息。
- Token 失效。
- 请求失败及重试操作。

分页栏显示上一页、当前页/总页数、下一页。按钮尺寸固定；第一页和最后一页分别禁用对应按钮。

### 5.3 图片预览

点击图片后打开 `Modal`：

- 主体展示适应窗口的大图，不拉伸、不裁切。
- 展示文件名、尺寸、文件大小、MIME 类型、上传时间和公开状态。
- 展示引用次数和引用笔记数，并允许展开查看引用笔记列表。
- 点击引用笔记可在 Obsidian 中打开对应笔记。
- 提供复制原图链接、复制 Markdown、在浏览器打开和删除操作。
- 从预览中删除成功后关闭弹窗，并刷新或更新图库页。

优先使用原图链接作为 `<img>` 来源。若私有图片不能直接加载，降级为携带 Bearer Token 请求二进制内容、创建临时 Blob URL，并在弹窗关闭时调用 `URL.revokeObjectURL()`。

## 6. 删除安全设计

删除图片属于不可撤销操作，必须满足以下约束：

1. 图片卡片和预览中的删除按钮都先打开确认对话框。
2. 对话框展示缩略图、文件名、引用次数和引用笔记数，并明确说明“删除后图床链接将失效，笔记中的引用不会自动移除”。
3. 存在引用时以警示状态列出最多 5 个受影响笔记；其余数量汇总显示。引用次数为 0 时仍提示统计范围仅限当前仓库。
4. 取消是默认安全操作；确认按钮使用警示样式并显示“永久删除”。
5. 删除请求进行中禁用确认按钮，防止重复提交。
6. 只有服务端确认成功后才从界面移除图片。
7. 删除失败时保留图片，展示服务端错误并允许重试。
8. 首期不提供批量删除和跳过确认的设置。

删除当前页最后一项后：

- 若当前页大于 1，加载上一页。
- 否则重新加载第一页并显示空状态。

## 7. 客户端数据模型

```ts
type ImageOrder = "newest" | "earliest" | "utmost" | "least";
type ImagePermission = "public" | "private";

interface ImageQuery {
    page: number;
    q?: string;
    order: ImageOrder;
    permission?: ImagePermission;
    albumId?: number;
}

interface BeeImgImageLinks {
    url: string;
    thumbnailUrl: string;
    markdown?: string;
}

interface BeeImgImage {
    key: number;
    name: string;
    pathname: string;
    mimetype: string;
    extension: string;
    size: number;
    width: number;
    height: number;
    date: string;
    humanDate: string;
    links: BeeImgImageLinks;
}

interface ImagePage {
    items: BeeImgImage[];
    currentPage: number;
    lastPage: number;
    perPage: number;
    total: number;
}
```

API 原始字段只在客户端解析边界出现，视图只消费统一后的 camelCase 数据。查询参数使用 `URLSearchParams` 构建，空条件不发送。

`BeeImgClient` 新增：

```ts
listImages(query: ImageQuery): Promise<ImagePage>;
deleteImage(key: number): Promise<void>;
```

删除响应没有 `data` 字段，因此响应信封类型应允许 `data` 缺省，不能为了复用上传响应类型而伪造数据。

## 8. 当前仓库引用索引

### 8.1 计数规则

引用统计严格遵循 [CONTEXT.md](../CONTEXT.md) 的定义：

- 只统计当前仓库中的 Markdown 文件，关闭的笔记也包含在内。
- 只统计 Obsidian 元数据缓存识别出的图片嵌入，不统计普通 Markdown 链接或纯文本 URL。
- 同一笔记嵌入同一图片 3 次，引用次数为 3、引用笔记数为 1。
- 两篇笔记分别嵌入一次，引用次数为 2、引用笔记数为 2。
- 缩略图链接不代表笔记正在使用图片，只使用原图链接进行匹配。
- 图片删除后引用仍保留在笔记中，统计不会自动变为 0；图库刷新后该图片不再出现在远端列表。

首期不统计 Canvas、PDF、附件元数据和普通 HTML 超链接。原始 HTML `<img>` 是否进入计数取决于 Obsidian 是否把它暴露为 `CachedMetadata.embeds`，实施前必须验证并在 README 中说明最终支持范围。

### 8.2 URL 匹配

图库返回的 `links.url` 与 `EmbedCache.link` 在比较前执行相同的规范化：

1. 仅接受 `http:` 和 `https:` URL。
2. 使用标准 `URL` API 解析并生成规范地址。
3. 忽略 URL fragment，因为它不改变远端图片资源。
4. 保留 query string；带不同变换或签名参数的地址不默认视为同一引用。
5. 路径大小写保持不变，不按文件名、pathname 或 MD5 猜测匹配。
6. 无法解析的链接不计数，不阻塞其他笔记的索引。

该规则优先避免误报。后续若需要识别 CDN 域名切换或历史域名，应建立明确的站点别名设置，不能通过模糊字符串比较实现。

### 8.3 索引模型

```ts
interface ImageUsageSummary {
    referenceCount: number;
    noteCount: number;
    notePaths: string[];
}

interface FileImageReferences {
    filePath: string;
    countsByUrl: Map<string, number>;
}
```

索引维护两个方向的数据：

- `filePath -> URL/count`：便于笔记变化时撤销该文件的旧贡献。
- `URL -> filePath/count`：便于图库按原图链接 O(1) 查询引用次数和受影响笔记。

引用信息不属于远端 `BeeImgImage`，视图通过 `usageIndex.getUsage(image.links.url)` 单独查询，避免把当前仓库状态混入 API 数据模型。

### 8.4 建立与更新

索引在用户首次打开蜜蜂图库时延迟建立：

1. 立即遍历 `vault.getMarkdownFiles()`，读取每个文件的 `metadataCache.getFileCache(file)?.embeds`。
2. 已有缓存的文件立即加入双向索引；缓存尚不可用的文件进入 pending 集合。
3. 通过后续 `changed/resolved` 事件补齐 pending 文件，不能假设首次打开图库时 `resolved` 尚未触发。
4. 规范化所有外部图片嵌入并建立双向索引。
5. 图片列表可以先显示；索引建立期间引用数字显示加载状态，完成后局部更新当前卡片。

初始建立后监听：

- `metadataCache.changed`：撤销该文件旧贡献并从新缓存重新加入。
- `metadataCache.deleted`：移除被删除文件的贡献和 pending 状态。
- `vault.rename`：迁移文件路径；元数据缓存不会因重命名触发 `changed`。
- `metadataCache.resolved`：重新检查 pending 文件；pending 清空后标记索引就绪。

插件卸载时注销事件。图库视图关闭后索引可以保留到插件卸载，避免同一会话再次打开时全量重建。

### 8.5 一致性与降级

- 索引状态分为 `idle`、`indexing`、`ready` 和 `error`。
- 某个文件缓存暂不可用时不把它当作“无引用”，而是等待后续 `changed/resolved` 事件。
- 索引发生局部错误时保留其他文件的统计，并在图库状态区提示“部分引用可能尚未统计”。
- 引用次数只能证明当前仓库内的已识别 Markdown 图片嵌入；删除确认不得声称图片在其他仓库或外部系统中未使用。
- 不把索引写入 `data.json`，避免路径和笔记关系形成过期持久数据。

## 9. 代码组织

保持现有上传逻辑不动，新增图片管理模块：

```text
main.ts                    # 插件生命周期、现有客户端、视图注册和入口
image-manager.ts           # 领域类型、图库 ItemView、预览和删除确认 Modal
image-usage-index.ts       # 当前仓库图片引用索引及增量事件处理
styles.css                 # 图库、工具栏、网格、预览及响应式样式
```

`image-manager.ts` 定义视图所需的最小客户端接口，由 `BeeImgClient` 结构化实现，避免反向导入 `main.ts` 造成循环依赖。若后续全面迁移 v2，再把 API 客户端拆成独立文件。

插件生命周期：

- `onload()` 注册视图、命令和功能区图标。
- `activateImageManager()` 查找已有视图；不存在时创建，存在时激活。
- `onunload()` 由 Obsidian 注销视图；视图负责清理定时器和 Blob URL。

## 10. 状态与并发

图库视图维护以下状态：

```ts
interface ImageManagerState {
    query: ImageQuery;
    page: ImagePage | null;
    status: "idle" | "loading" | "ready" | "empty" | "error";
    usageStatus: "idle" | "indexing" | "ready" | "error";
    errorMessage: string;
}
```

请求并发规则：

- 每次查询递增请求序号，只允许最新请求更新界面。
- 搜索输入使用 300 ms 防抖；其他筛选立即查询。
- 筛选条件改变后页码重置为 1。
- 刷新保留当前查询和页码。
- 视图关闭时清理防抖计时器；迟到的响应不得重新渲染已关闭视图。
- 删除操作按图片 Key 互斥，同一图片不能同时提交多个删除请求。
- 远端图片查询与本地引用索引互不阻塞；任一方就绪都可以先更新对应区域。
- 索引变化只更新当前页中原图链接受影响的卡片，不重新请求图库 API。

## 11. 错误处理

| 场景 | 行为 |
|---|---|
| 未配置 Token/账号 | 显示认证空状态，引导用户前往插件设置 |
| HTTP 401 | 显示 Token 已失效；账号密码模式可复用现有重新登录策略后重试一次 |
| HTTP 403 | 显示当前 Token 无权查看或删除图片，不误报为网络错误 |
| HTTP 404 删除 | 视为图片已不存在，刷新当前页并提示状态已同步 |
| HTTP 429 | 保留当前内容，提示请求过于频繁并允许手动重试 |
| 5xx/网络失败 | 保留上一次成功内容，在状态区显示非阻塞错误和重试按钮 |
| 缩略图加载失败 | 显示固定尺寸占位和文件类型，不影响其他卡片 |
| 响应结构异常 | 报告“服务端返回格式不兼容”，不渲染部分未知数据 |
| 元数据缓存未就绪 | 保持引用计数加载状态，等待 `resolved` 后更新 |
| 部分笔记索引失败 | 显示统计不完整提示，删除确认不得显示“未被使用” |

所有来自 API 的名称和错误内容按纯文本渲染，不使用 `innerHTML`。

## 12. 性能、隐私与可访问性

- 服务端分页，不一次性拉取全部图片。
- 缩略图懒加载；卡片使用固定宽高比，防止布局跳动。
- 搜索防抖并忽略过期响应。
- 引用索引初次建立复杂度与 Markdown 图片嵌入总数线性相关；笔记变化只重算单个文件。
- 卡片按规范化原图 URL 常数时间查询引用统计，不为每张远端图片重复扫描仓库。
- 不把图库响应写入插件持久化数据，只在视图生命周期内保留。
- 不持久化笔记路径和引用关系。
- 不记录 Token、原图二进制或完整 API 响应到控制台。
- 图标按钮通过 Obsidian `setIcon` 使用内置 Lucide 图标，并设置 `aria-label` 与 tooltip。
- 所有操作均可通过键盘聚焦；预览和确认弹窗遵守 Obsidian Modal 的焦点管理。
- 文件名允许换行或省略显示，不能撑破卡片和工具栏。
- 移动端不依赖 hover 才能发现删除等关键操作。

## 13. 测试策略

### 13.1 单元测试

- 查询参数构建：空值省略、特殊字符编码、相册和筛选映射。
- v1 列表响应规范化：完整字段、空列表、缺失链接和分页边界。
- 错误映射：401、403、404、429、5xx 和非 JSON 响应。
- 删除响应：成功、重复提交和失败后状态恢复。
- 请求序号：迟到响应不能覆盖最新查询。
- 页尾删除：回到上一页或进入空状态。
- URL 规范化：协议/主机规范化、fragment 忽略、query 保留和非法 URL。
- 引用统计：同一笔记重复引用、多笔记引用、普通链接排除和缩略图链接排除。
- 增量索引：笔记修改、删除、重命名以及缓存迟到。
- 索引不完整时删除确认不能显示确定性的“0 次引用”。

实现阶段增加与现有 Node 18 CI 兼容的轻量测试运行器，并把测试加入 `npm run build` 之前的 CI 步骤。

### 13.2 手动验证

- API Token 与账号密码两种认证模式。
- 空图库、单页、多页以及超过一页的相册筛选结果。
- 中文、空格和超长文件名。
- PNG、JPEG、GIF、WebP、SVG，以及缩略图加载失败。
- 公开和私有图片预览。
- 删除普通图片、当前页最后一项以及服务端已删除图片。
- 桌面宽屏、窄侧栏和移动端布局。
- 删除前取消，确认后成功，以及删除请求失败。
- 当前笔记重复嵌入、多个笔记嵌入，以及关闭笔记中的引用计数。
- 编辑、删除和重命名引用笔记后，图库数字无需重新打开即可更新。
- 大型仓库建立索引时图库仍可浏览，统计完成后不发生布局跳动。

## 15. 验收标准

- 用户能从功能区或命令面板打开唯一的“蜜蜂图库”视图。
- 默认按最新顺序显示当前账号图片，并能正确分页。
- 搜索、相册、公开状态和排序筛选能组合使用。
- 每个下拉选项和图片操作均有明确名称，长文本不破坏布局。
- 缩略图可加载，点击后能查看适应窗口的原图和元数据。
- 每张图片显示当前仓库引用次数；同一笔记重复引用会分别计数。
- 新增、移除或重命名引用笔记后，计数在当前会话内自动更新。
- 预览可以查看引用笔记数和笔记列表，并能打开对应笔记。
- 用户可以复制原图链接和 Markdown。
- 删除必须经过确认；确认内容包含引用影响，取消不发送请求，成功后列表同步，失败时图片保留。
- 401、403、空结果和网络失败均有独立且可恢复的界面状态。
- 现有粘贴、拖拽、剪贴板和批量上传功能行为不变。
- `npm run build`、新增单元测试和发布工作流全部通过。

## 16. 实施前验证项

以下事项需使用真实账号在开发环境确认，但不阻塞编码准备：

1. 旧版列表的 `size` 单位是否始终为字节。
2. 私有图片的 `links.url` 和 `thumbnail_url` 能否直接作为 `<img src>` 加载。
3. 现有持久 Token 是否均可调用旧版删除接口，还是存在额外服务端权限限制。
4. 删除成功响应是否稳定为 HTTP 200 且 `status=true`。
5. GIF 或超大原图在移动端预览时的内存占用是否需要尺寸限制。
6. `CachedMetadata.embeds` 是否覆盖外部 Markdown 图片、带标题的图片语法和原始 HTML `<img>`。
7. 元数据缓存尚未完成初始解析时，`resolved` 事件与图库首次打开的顺序。
